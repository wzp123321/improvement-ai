# 原型契约规范（UI Prototype Standard）

> 本规范定义**阶段一 UI 原型**的产出契约：产出形态、结构分析、五态演示、数据接入、样式边界与 `_notes.md` 交接。
>
> **定位**：本文件是【天溯自有契约】，与 `references/design-systems/tiansu-web/DESIGN.md`（品牌观感）、`references/rules/hifi-craft.md`（品牌无关工艺增强层）**三者互补**：
>
> | 层 | 文件 | 管什么 |
> |---|---|---|
> | 契约层（本文件） | `references/rules/ui-prototype-standard.md` | 原型**结构**：形态、区域、状态、数据接入、交接格式 |
> | 品牌层 | `references/design-systems/tiansu-web/DESIGN.md` + `tokens.css` | 原型**观感**：色/字/间距/组件的天溯纪律 |
> | 工艺层 | `references/rules/hifi-craft.md` + `references/assets/open-design/craft/` | **通用工艺**：反 AI 味、排版、动效、无障碍、五态 |
>
> 冲突时以本文件（契约）与 `DESIGN.md`（品牌）为准；工艺层为增强，不覆盖二者。
>
> **消费方**：阶段一 UI 子 agent（产出）、阶段二 `ts-design` SKILL §2.4（读原型落组件级布局）、`ts-design-review`（评审核对）。

> ## ⚠ 2026-09-10 形态变更：原型 = 真 Vue SFC
>
> 本规范原定义「自包含单文件 HTML，不绑定真实组件运行时」。该形态已**作废**，原因是它解决错了问题：
> 它把「组件选型」推迟到阶段二，于是阶段一产出的视觉稿与最终实现**必然不一致**——字号、间距、圆角、
> 控件形态、交互反馈全都是手写近似值，阶段二拿到的是「一张长得像的图」而不是可落地的结构。
>
> **新形态**：原型是**真正的 Vue 3 + TS 单文件组件**，由 `te-*` 真组件组合而成，可直接构建渲染。
> 组件选型因此在阶段一就完成并被真实验证，不再有「阶段二重新选一遍」这一步。
>
> 已按旧形态归档的 HTML 稿（如 `ui-V3.3.0_I1_接入OD/`）为**历史遗留**，不再新产出，也不必回改。
> 本次变更由 `archive-spec/product/ui-V3.1.0_I2_设备台账列表/` 这份试验件驱动；实测依据见该目录 `_notes.md`。

> ## ⚠ 2026-09-11 落位变更：原型住进项目，不再自建脚手架
>
> **背景**：上一版让原型在「与两个仓库都无关的临时 Vite 工程」里验证（§6 旧文）。那个工程是
> **项目的仿制品**——它自己重装一遍 `TsWebPackage`、自己声明 alias 与版本。于是
> 「必须整体安装，否则 `te-search` 静默消失」（§1）这类坑，恰好出现在仿制品可能与真项目分叉的地方；
> 验证结论也就只对仿制品成立。而 §3.3 本来就要求原型对应 `src/views/<module>/index.vue`——
> 让它在项目里跑，才是真正验证了那个目标。
>
> **新落位**：原型 `.vue` 放**项目根 `prototype/`**，用**项目自己的** `node_modules` 与 dev server
> 跑起来。运行壳见 `references/assets/prototype-sandbox/`。组件库版本、主题、Vue 与编译器版本全部来自项目本身，
> 「组件选型在阶段一被真实验证」这句话才真正成立。
>
> **三条连带**：
>
> - `archive-spec/product/ui-*/` **只留 `_notes.md` 交接件**，不再存 `.vue` 副本——原型只有一份，
>   跑得起来的那份就是真相，不再有「归档版 vs 运行版」的第二套真相。
> - `src/` **仍全程不碰**：`prototype/` 在项目根、不在 `src/` 下。故 `references/hard-gate.md`「详细设计门禁」的
>   「不创建任何 `src/` 下的文件」与阶段一产物校验门禁**均不需修改**。
> - 实现时原型**晋升**：`.vue` 移入 `src/views/<module>/index.vue`，按 `references/rules/vue-standard.md` §3.1
>   补齐 `constant.ts` / `hooks/` / `modules/`，接真 API，删演示脚手架，`prototype/` 里**不留副本**。
>
> 上一版按临时脚手架验证的结论（`ui-V3.1.0_I2_设备台账列表/`）**仍然有效**，只是验证场所换了。

## 1. 适用范围与产出形态

**何时适用**：阶段一产出 UI 原型时（有页面场景）；`ts-design` **读取**原型落实组件级布局时（§2.4，不重新生成）；`ts-frontend-design` 作为独立视觉稿入口或工艺引擎被调用时。

**产物形态**：

- **Vue 3 + TypeScript 单文件组件（`.vue`）**，`<script setup lang="ts">`，由真 `te-*` 组件组合。
- **落位：项目根 `prototype/`**（不在 `src/` 下）。运行壳（`index.html` / `main.ts` /
  `vite.config.ts` / `tsconfig.json`）来自 `references/assets/prototype-sandbox/`，依赖用**项目的**
  `node_modules`——不新建 `package.json`、不另装一份组件库（§3.2、§6）。
- **可构建、可渲染、可截图**：在项目自己的 dev server 里跑起来并真实渲染；交付前必须**看过截图**。
- 视觉**来自组件库主题**，不来自本文件手写的样式。
- **PNG 可选**（导出/缩略，非门禁必需）。

**接入前提（三条，缺一不可）**：

1. **依赖**：`@tiansu/ts-web-package`（≥2.0.0；<2.0.0 走 `@tiansu/element-plus`，版本判据见 `ts-components`）。
2. **必须整体安装组件库**，不能只按需 `import`：

   ```ts
   createApp(App).use(TsWebPackage).mount('#app')
   ```

   原因：`te-tablebar` 等组件内部用 `resolveComponent('te-search')` **按名**取子组件。
   只按需 import 时解析失败，渲染成空的未知标签——**搜索框整块消失且不报任何错**。
3. **组件 API 必须经 `ts-components` 核实**（`tsweb info` / `tsweb doc` / `tsweb demo`），
   不凭记忆写 Props。详见 ``ts-components` 技能内的 `references/code-generation.md`` 五条红线。

**不写什么**：像素级样式复刻；覆盖组件默认外观的 CSS（见 §7）；任何 `src/` 下的文件；
除 `prototype/` 与 `archive-spec/` 外不在项目里新增文件。

## 2. 结构分析方法（三步，先于动手）

拿到参考图 / 截图 / 已有页面时，**按序走完三步再动手**；任一步信息不足则**提问**，不假设。

| 步 | 步骤 | 要得出什么 | 信息不足时 |
|---|---|---|---|
| 1 | **来源确认** | 输入是参考图 / 已有页面 / 纯文字描述？目标视口？ | 问清来源与目标视口 |
| 2 | **区域划分** | 页面由哪几个功能区组成、区与区的边界与顺序 | 划分不清时回问 |
| 3 | **区域 → 组件** | 每个区对应哪个 Te 组件；组件能否承载该区信息 | 组件选型不确定时走 `ts-components` 核实 |

> **本节的缩减**：原「六步法」含视口栅格、字号层级、颜色角色三步。这三步在旧形态下必要——
> 手写 CSS 必须自己造出全套视觉值。真组件形态下它们**是组件库和主题的职责**，
> 页面再推一遍只会推出与主题不一致的近似值。故删除，不保留。
>
> **仍需要「视觉方向」判断的场景**：页面含**组件库覆盖不到的自定义区域**时
> （图表、画布、时间轴定制、大屏等），该区仍需能一句话描述方向，按 `references/rules/hifi-craft.md` 做。

## 3. 页面结构与归档命名

### 3.1 页面锚点 S-xx

- 页面**从 PRD 场景脊椎 S-xx 推导**，不新增场景外页面。
- 纯规则 / 无页面场景：**不产出原型**，与前端概设 §3.1 对齐时留空说明。
- 页面清单与前端概设 §3.1 以 S-xx **双向核对**；不一致回 PRD 判定。

### 3.2 落位与命名（唯一口径）

原型有**两个位置**，各司其职，**不是两份副本**：

```text
<项目根>/prototype/                          ← 原型实件（唯一真相，跑得起来的那一份）
    index.html  main.ts  vite.config.ts  tsconfig.json   ← 运行壳，来自 references/assets/prototype-sandbox/
    <页面名>.vue                             ← 页面原型
    <Sxx>_<页面名>.vue                       ← 有 PRD 场景号时带 Sxx 前缀

archive-spec/product/ui-V<MAJOR>.<MINOR>.<PATCH>_I<ITERATION>_<描述≤6字>/
    _notes.md                                ← 交接件（见 §10），**只有这一个文件**
```

**命名铁律**（两处一致）：

- 场景号**下划线 + 两位补零**：`S01`、`S02`……**不是** `S-01`。
- 场景号与页面名之间用**下划线** `_` 连接：`S01_公告列表.vue`。
- 页面名用中文业务名，不加空格、不加连字符。
- **不再按状态拆份**：五态由文件内的演示场景切换器逐屏切换（§5.3）。旧形态靠拆多个 `.html` 表达状态，SFC 下拆分只会造成同一页面多份代码互相漂移。

**两个位置的分工**：

| 位置 | 内容 | 进 git | 生命周期 |
|---|---|---|---|
| `<项目根>/prototype/` | 原型 `.vue` + 运行壳 | **否**（`.gitignore` 加 `prototype/`） | 阶段一产出 → 实现时晋升进 `src/` 后消失 |
| `archive-spec/product/ui-*/` | 仅 `_notes.md` | **是** | 长期保留，承担可追溯性 |

> **为什么不各存一份**：同一份原型存两处必然漂移——改了一边忘另一边，评审时以谁为准会成为新问题。
> 跑得起来的那份就是真相；归档里那份换成**交接件**，记录映射、占位与未决问题，这才是实现者真正要读的。

**独立视觉稿（无 PRD / 无 S-xx）**：同样落在 `<项目根>/prototype/` 下，直接用 `<页面名>.vue`，
并在 `_notes.md` 的「页面清单」标注「独立视觉稿，无 PRD 场景」。

**一次只住一个迭代**：`prototype/` 是扁平目录。上一迭代若尚未实现又来了新迭代，
**先处置旧原型**（晋升或删除）再放入新的，不要让两个迭代的 `.vue` 共处一室——
`main.ts` 只挂一个原型，共处只会让「当前在预览哪一个」变得靠猜。

> ⚠ **全仓库落点与命名必须与本节一致。**
>
> - 历史文档中出现的 `S-01-页面名.html`（连字符）写法**作废**。
> - `.html` 后缀（含 `Sxx_页面名_状态.html` 的状态拆份写法）**作废**——2026-09-10 随形态变更一并废止。
> - `archive-spec/prototype/`、`archive-spec/visual/` 两个旧落点**一并作废**，统一收敛到本节。
> - 「归档 `ui-*/` 里放 `.vue`」**作废**——2026-09-11 随落位变更改为上表的分工。

### 3.3 页面骨架节奏（Te 中后台）

中后台页面有固定节奏，**禁止每页发明布局**：

```text
页面标题 → 查询区(te-tablebar) → 工具条 → 表格(TeModuleTable) → 分页
新增 / 编辑 / 删除 → 弹窗(te-dialog > te-form)；详情 → te-descriptions
```

落位：页面文件置于 `src/views/<module>/index.vue`。**应用外壳**（Layout / 侧边导航）由 `src/components/`
提供，**不写在页面文件里**（`references/rules/vue-standard.md` §3.1）。

## 4. CJK 排版纪律

### 4.1 适用范围（2026-09-10 收窄）

本节**只管页面自己写的文本**，不管组件内部文本。

组件渲染出来的标题、正文、按钮、表格单元格——其字号 / 行高 / 字距**由组件库主题决定**，
页面不得再指定，指定了就是覆盖组件默认外观（违反 §7）。

因此本节的适用对象是：空态文案、`te-result` 的标题与副标题、自定义区域的文本、
`_notes.md` 里要求页面自带的说明性文字。

### 4.2 硬性数值

**行高**

| 文字类型 | 字号 | 行高 | 说明 |
|---|---|---|---|
| 大标题 | ≥32px | **1.3–1.4** | 中文大标题不加负字距 |
| 中标题 | 20–28px | 1.4–1.5 | — |
| 正文 | 14px | **1.7–1.8** | 中后台正文基准 |
| 辅助/次要 | 12px | 1.6–1.7 | 次要说明文字 |

**行宽**：正文行宽 **≤ 65ch**；超过则收窄内容容器，**不让整页跑满 4K**。

**字距**

| 场景 | 字距 |
|---|---|
| 全大写西文 | **0.06–0.1em**（必加） |
| 小字（≤12px） | 0.01–0.02em |
| **中文标题** | **0（禁止负字距）** |
| 中文正文 | 0（默认不调） |

**字重**：三档（400 / 500–550 / 600），**很少 700+**。**不写档外字号**（如 13px）。

### 4.3 字族

- 默认 `--te-font-family`（西文 Helvetica 系 + PingFang/微软雅黑回退）。
- 数字想让"工程感"更强时显式指定 `--te-font-family-d-din` / `-d-din-bold`。
- `YouSheBiaoTiHei` **没有对应 `--te-*` 变量**，要用直接写字面族名，勿自造变量。
- 字族总数 **≤ 2 + 系统 fallback**。

## 5. 状态覆盖与演示实现

### 5.1 五态契约

凡**拉取 / 接收数据**的区域，五种状态**必须齐全**：

| 状态 | 含义 | 要求 |
|---|---|---|
| `loading` | 请求中 | 用组件的内置加载态；组件无内置态时才自建，不用无限转圈 |
| `empty` | 请求成功但无数据 | 讲人话 + 给**主操作**入口；区分「从未有数据」与「筛选后无结果」 |
| `error` | 请求失败 | 文案 = 出了什么 + 可知的原因 + 能做什么 |
| `populated` | 有数据 | 默认态 |
| `edge` | 边界数据 | 超长文本截断、单条、万级条数、超长枚举等 |

**铁律**：`error ≠ empty`。两者用不同的视觉与文案，不得互相顶替。

### 5.2 数据接入：列表类区域必须走 `request-api`

**这是本节最重要的一条。** `te-module-table` 有两条入参路径：静态 `:data` 与 `:request-api`。
原型**必须走 `:request-api`**，用本地 mock 兑现接口契约。

理由不是风格偏好，是实测：静态 `:data` **绕过了 `useTable` 数据管线**，导致三处区域静默损坏——

| 症状 | 根因 |
|---|---|
| 操作列整列空白，只剩一个注释节点 | `TeTableButtonGroup` 的渲染被 `row.parentIndex` 守卫，该字段由 `useTable.setRowIndex()` 注入 |
| 分页完全不出现 | 分页容器被 `pagination && pageInfo.total > 0` 守卫，静态数据没有 `total` |
| 序号列无数字 | 序号列渲染 `row.isIndex ? row.parentIndex : 注释`，两个字段同来自 `setRowIndex()` |

三处**都不报错**，只是安静地空掉。这是「原型看起来对、实现后全塌」的典型来源。

**接口契约**：

```ts
api(params) => Promise<{ data: { rows: T[], total: number } }>
// params = { ...筛选条件, ...initParam, pageNum, pageSize }
```

- 后端响应不是这个形状时，用 `:data-callback` 适配（官方 Demo 即如此）。
- `total: 0` 能通过组件的真值判断（`"0"` 是非空字符串），空列表走正常分支，不会误入兜底。
- **筛选必须真实生效**：空态应由筛选逻辑算出，不是模板里的假分支。

这样 loading / 空态 / 分页 / 序号 / 行操作**全部由组件内置能力产生**，
不需要「用模板分支假装五态」——后者正是旧形态可信度低的根源。

**刷新走暴露的 API，不重建组件**：查询 / 刷新 / 重置调 `tableRef` 暴露的
`getTableList()` / `reset()` 等；重建组件会把「更多搜索」展开状态和已勾选行一起丢掉。

### 5.3 演示实现

原型需**可切换演示**五态。SFC 形态下的标准做法：

- 页面顶部放一个**演示场景切换器**（一组 `te-button`），切换它**改变 mock 接口的返回**
  （正常 / 延迟不结算 → loading / 空数组 → empty / reject → error / 超长数据 → edge）。
- 切换器与 mock 数据**必须在代码里用 `⚠ 演示脚手架` 注释显式标出**，并在 `_notes.md`「待替换占位」逐条列出。
- 切换器同时暴露到 `window.__odScenario`（一行，同样标 `⚠ 演示脚手架`），供无头截图脚本逐屏驱动。
  否则五态验证只能靠 DOM 猜按钮位置，脆弱且难复现；该行同样进「待替换占位」，实现时一并删。
- 五态必须在**同一交付内可逐屏看到**，不能只交正常态。

> 旧形态的「拆成多份 HTML」已废止（§3.2）。旧形态的「内联 JS 切 `data-state` + CSS 显示对应态」
> 亦不再使用——那正是「假装」的来源。

### 5.4 交互控件的状态

控件状态（`hover` / `focus-visible` / `active` / `disabled` / `loading`）**由组件库提供**，页面不再自建。

页面只需保证**语义正确**：

- 状态机不允许的动作**不做入口**（不出现"点了才报错"的按钮）。
- 批量操作未选中时**禁用**。
- 危险操作独立 `danger` 语义 + 二次确认，不用主色顶替。

### 5.5 动效纪律

- **组件内部动效由组件库决定**，页面不得覆盖其曲线与时长。
- 页面自建区域（自定义图表、自绘容器）的动效：曲线 `cubic-bezier(0.2,0,0,1)`；
  时长 即时 50–100 / 状态确认 150 / 进入 200–300 / 跨屏 300–500ms。
- 自建动效默认处理 `prefers-reduced-motion`：关闭轴向运动，淡入淡出可保留。

> **待裁定**：本规范原统一规定曲线为 `cubic-bezier(0.2,0,0,1)`，而组件库主题用 Element Plus 曲线。
> 真组件形态下两者会**并存**（组件用一套、自建区域用另一套）。是否统到组件库曲线，见 §10「未决问题」。

## 6. 运行与验证

原型不再是「双击打开」的自包含文件，验证方式是**在项目里把它跑起来**。

**准备沙箱**（每个项目一次性）：

1. 把 `references/assets/prototype-sandbox/` 的四个文件拷到 `<项目根>/prototype/`。
2. `main.ts` 里组件库与主题的引入方式**照项目 `src/main.ts` 抄**——版本、路径、语言包、
   全局指令都抄它。沙箱自己另挑一套引法，就失去了「验证项目里长什么样」这个唯一目的。
3. `main.ts` 的 `import Prototype from './Sxx_页面名.vue'` 指向当前原型。
4. 项目 `.gitignore` 加一行 `prototype/`。
5. **不新增依赖、不新建 `package.json`**：`vite` / `@vitejs/plugin-vue` / `vue` / 组件库
   全部从项目的 `node_modules` 向上解析——用的就是项目同版本的 Vue 与编译器。

**怎么跑**：

```bash
cd prototype
npx vite                 # 起 dev server，看渲染
npx vite build           # 一次构建检查
```

**交付前必须做到**：

- **构建通过**：`vite build` 无报错。
- **真实渲染过并看过截图**——空白页 / 半截页面即不算通过。
- **五态逐屏验证**：用 §5.3 的场景切换器逐屏过一遍，确认五态都能看到且文案正确。
- **依赖写进 `_notes.md`**：组件库版本号，以及「必须整体安装」（§1）这一条。
- **确认对项目零影响**：`prototype/` 是独立入口，默认不进生产构建、不进项目 `tsconfig` 的
  `include`。项目若自定义了多入口构建或全仓库 `include`，把 `prototype/` 排除——
  排查结论写进 `_notes.md`「待替换占位」。

> `_notes.md` 的截图与 `/tmp` 中间产物**均不得进 git**；`prototype/` 本身也不进 git（§3.2）。

**无头截图与实测坑**：见 `references/assets/prototype-sandbox/README.md` 末节。那里记着
「无头虚拟时间下过渡不结束」「压 `display` 会把 `te-tablebar` 查询区压塌成竖排」
这类够具体、能省一整轮排查的结论，遇到再翻。

## 7. 值源与样式边界

### 7.1 值源

- **颜色 / 字号 / 间距 / 圆角 / 阴影的唯一值源 = 组件库主题**（运行时由 `@tiansu/ts-web-package` 提供）。
- 页面需要主题变量时，直接用**运行时语义变量名**（`--te-space-*` / `--te-color-*` / `--te-text-color-*`…）。
- **禁止**：自定义 `--p-*` 前缀变量；把主题快照抄进 `:root`；用 `tsweb design` 的返回值在页面里重建一套视觉值。
  （这三条是旧形态的产物——旧形态没有组件运行时，只能自己造值；现在有了，再造就是制造不一致。）

### 7.2 样式边界（红线 #3 的原型侧表述）

**默认样式不需要覆盖。不在 `<style>` 里写额外 CSS。**

允许写的样式**只有页面级布局**：

| 允许 | 例 |
|---|---|
| 页面区块的纵向/横向排布 | `.device-ledger { display:flex; flex-direction:column; gap:var(--te-space-16) }` |
| 页面自己插入的容器的排布 | 条件区横排容器 `.query-row`（组件不给 `#searchList` 内布局） |
| 页面自建区域的全部样式 | 自绘图表容器等 |

不允许：

| 不允许 | 为什么 |
|---|---|
| 改组件的颜色 / 字号 / 行高 / 圆角 / 内边距 | 覆盖组件默认外观，与主题脱节 |
| 用 `:deep()` 进组件内部 | 耦合组件私有结构，组件升级即坏 |
| 复制组件库 CSS 再改 | 同上，且必然漂移 |

**自发检查**：如果 `<style>` 里出现了色值、字号、圆角，先问「这是页面级布局吗」——
不是就删掉。正例反例见 §9.3。

- 间距取 `--te-space-*` 档位（4/8/12/16/20/24/32/40/48/64/80/96/160），**不写随机 px**。
- 反 AI 味 P0（蓝紫强调色、双色渐变、emoji 当图标、编造指标、lorem 占位）见 `references/rules/hifi-craft.md` §5。
  真组件形态下这类问题多来自**自建区域**，组件区基本不会出现。

## 8. 交互与权限显隐

- 按钮**显隐 / 禁用**必须与后端概设**权限矩阵**一致。
- 状态机**不允许的动作不做入口**（不出现"点了才报错"的按钮）。
- 危险操作独立 `danger` 语义 + **二次确认**，不用主色顶替"危险"。
- 二次确认的**文案写明后果**，不写「确定吗？」。
- 文案：按钮 = 动词 + 对象；全站同动作同词；UI 中文业务词；**emoji 不作功能图标**。

## 9. 区域 → 组件映射

### 9.1 映射就在模板里

旧形态下原型是 HTML，没有组件身份，只能靠 `data-ui-role` 属性给实现侧一个机器可读锚点。
**真组件形态下这个需求消失了**：区域**就是**组件本身，映射在模板里直接可见。

```vue
<te-page-header title="设备台账" content="全站设备的基础档案与运行状态">…</te-page-header>
<te-tablebar v-model="keyword" …>
  <template #searchList>…</template>
  <template #suffix>…</template>
</te-tablebar>
<te-module-table :request-api="requestApi" …>
  <template #status="{ row }"><te-tag :type="…">{{ row.status }}</te-tag></template>
  <template #operation="{ row }"><te-table-button-group … /></template>
</te-module-table>
```

读这段代码就知道：查询区是 `te-tablebar`，表格是 `te-module-table`，状态列是 `te-tag`，
操作列是 `te-table-button-group`。**比 21 个角色词更精确，且不会说谎**——词表可能标了
`data-ui-role="toolbar"` 而实现选用别的东西，模板不会。

### 9.2 `data-ui-role` 词表：废止

**2026-09-10 随形态变更废止。** 原词表（21 个角色，含 `page-header` / `query-bar` / `data-table` /
`procedure-list` 等）及其「封闭词表」纪律**不再适用**，新原型**不写** `data-ui-role`。

废止理由：该词表是为「无组件身份的 HTML 原型」设计的替身锚点。真组件形态下它成了
**第二套真相**——同一个区域既有 `data-ui-role` 标注、又有真实组件，两者不一致时以谁为准会成为新问题。

历史归档 HTML 稿中的 `data-ui-role` 保留原样，不必回改；但**不要**照抄进新的 SFC 稿。

> 旧词表中 `procedure-list`（运维手册类查阅型页面的操作步骤清单，2026-09-10 增补）的语义需求仍然存在：
> 该区在 SFC 稿里由**自定义区域**承载（容器 + 等宽代码块），按 §2 走「视觉方向」判断，
> 因为组件库没有对应组件。

### 9.3 正例与反例（§7.2 的白名单判定）

来自试验件 `archive-spec/product/ui-V3.1.0_I2_设备台账列表/`：

```css
/* ✅ 允许：页面区块纵向排布 */
.device-ledger { display: flex; flex-direction: column; gap: var(--te-space-16); }

/* ✅ 允许：页面自己插入的容器排布（组件不给 #searchList 内的布局） */
.query-row { display: flex; flex-wrap: wrap; gap: var(--te-space-16); padding: 0 24px; }
.query-field { width: 200px; }

/* ❌ 不允许：改组件外观（这里改的是 te-tag 的颜色） */
.te-tag { --te-tag-bg-color: #e8f5e9; }

/* ❌ 不允许：用 :deep 进组件内部改结构 */
.device-ledger :deep(.tlws-form-con) { display: flex; }
```

> 上例的 `.query-row` 是一条**经验**：`te-tablebar` 的 `.tlws-form-con` 只给了 `flex: 1`，
> 对插入的控件不做任何排布，默认竖排铺满整行，而官方 Demo 在该槽位只放占位 `<div>`，没有示范真实布局。
> 横排是页面自己的事——但**要包在自己的容器里**，不能 `:deep` 进去。

## 10. `_notes.md` 契约

每个原型归档目录**必须**附一份 `_notes.md`，作为**原型 → 阶段二**的交接件。最少包含：

| 小节 | 内容 |
|---|---|
| **页面清单** | 每个原型 `.vue` 的**沙箱路径**（`<项目根>/prototype/Sxx_页面名.vue`）、对应 S-xx 与页面名；是否为独立视觉稿；五态切换方式 |
| **区域 → 组件映射** | 逐区列出：区域名 / 实际使用的 Te 组件 / 该区承载的关键信息 / 具名槽名 |
| **token 使用** | 用到的 `--te-*` 变量及用途（页面级布局用的通常只有 `--te-space-*`） |
| **待替换占位** | mock 接口、演示脚手架、硬编码数据、临时回调，逐条列出 |
| **未决问题** | 需要阶段二确认的选型、映射多解、口径分歧；**以及本次实测发现的组件库坑** |

> `_notes.md` 是**给实现者的**，不是给评审者的总结。写得像交接单，不像报告。

**「未决问题」的新职责**：真组件形态下，原型是**第一个真正踩到组件库实现细节**的环节
（旧形态不碰运行时，踩不到）。因此该节必须记录实测发现，例如：
未进 `.d.ts` 但在运行时生效的 API、CLI 文档缺失的组件、组件的隐藏前置条件、
必须全局安装的内部耦合等。这些是团队最有价值的反馈来源。

## 12. 增强层：OD headless 能力（可选）

> **定位**：**增强，非依赖**。插件使用者（下游用户项目）**不具备** OD daemon 环境；本节能力不可用时**必须退化**为 §11 的人工清单，产出流程**不得中断、不得报错**。

### 12.1 能力检测

```
探测 127.0.0.1:<port> 上 OD daemon 是否可达
  ├─ 可达   → 启用 §12.2 / §12.3
  └─ 不可达 → 跳过，走 §11 人工清单
```

### 12.2 P0 反 AI 味门禁 —— ⚠ SFC 形态下暂不可用

原命令针对 HTML 文件：

```bash
od lint <原型>.html --fail-on p0 --json --daemon-url http://127.0.0.1:<port>
```

**SFC 不是 HTML，该命令不再直接适用。** 且其判据（蓝紫强调色、双色渐变、emoji 图标等）
主要针对手写 CSS——真组件形态下这些问题基本来自自建区域，覆盖面已大幅缩小。

**处置**：暂以 §11 的人工清单替代。是否值得为 SFC 重建该能力（如先构建再 lint 产物 HTML），
见 §10「未决问题」。

### 12.3 PNG 导出（可选产物）

```bash
od export <原型>.html --project <id> --format image --out <out> --daemon-url http://127.0.0.1:<port>
```

- 兑现"PNG 可选导出"；**非门禁必需**。
- 同 §12.2：入参为 HTML，SFC 需先构建。验证截图目前由 §6 的项目沙箱承担。

### 12.4 端口铁律

**必须显式传 `--daemon-url`。** daemon 端口**动态分配**（如经 `tools-dev` 启动时），CLI 默认的 `7456` 会 `ECONNREFUSED`。禁止假定固定端口。
