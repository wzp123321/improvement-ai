# 概设规范（阶段一）

> 本规范定义阶段一「概设（Overview）与 UI 产出」的执行标准。
>
> 阶段一：产品需求 → 主线程并行分派前端/后端两个子 agent 生成 后端概设 + 前端概设 → ⛔ 用户确认；**UI 由独立 UI 子 agent 经 openDesign 从 PRD 直接产出可构建渲染的原型（Vue 3 + TS 单文件组件，由真 `te-*` 组件组合）**（非概设文档），作为阶段一产物一并落位（原型 `.vue` 落**项目根 `prototype/`**，交接件 `_notes.md` 归档 `ui-*/`）、一并纳入阶段一产物校验门禁。概设确认后前后端分离：后端概设（主线契约）交付后端团队独立实现，前端产物（前端概设 + 后端概设契约 + UI 原型）为阶段二 ts-design 的直接输入。
>
> 阶段一归档产物 = **前端概设 + 后端概设 + UI 原型**（有页面场景时 UI 原型必须产出）：
>
> - 主线程基于 PRD **并行分派前端、后端两个子 agent** 生成概设：后端概设把 PRD 的业务契约翻译为领域模型、状态机、数据字典、接口契约、权限、消息事件并**定稿主线**；前端概设**引用后端契约**并落地前端支线（页面与路由、API 模块）。
> - **UI 不产生概设文档**：由**独立 UI 子 agent 经 openDesign**（产出前先读取 openDesign 设计规范）从 PRD S-xx 直接产出**真组件原型**（Vue 3 + TS SFC，`.vue`），落**项目根 `prototype/`**（`.vue` 为准、PNG 可选），交接件 `_notes.md` 归档 `ui-*/`，与概设并行产出、互不为输入，确认时以 S-xx 对齐；**不单独成文、不重复定义契约**，但作为阶段一 UI 产物**纳入阶段一产物校验门禁**（有页面场景缺产出 → 提示先完成阶段一）。
>
> ⚠ **2026-09-10 形态变更**：原型原为「自包含 HTML、不绑定组件运行时」，该形态已作废——它把组件选型推迟到阶段二，导致视觉稿与实现必然不一致。现原型是**真 Vue 3 + TS 单文件组件**，由真 `te-*` 组件组合、可构建可渲染，组件选型在阶段一完成并被真实验证。依据见 `references/rules/ui-prototype-standard.md` 卷首与 `archive-spec/product/ui-V3.1.0_I2_设备台账列表/_notes.md`。
>
> ⚠ **2026-09-11 落位变更**：原型 `.vue` 不再存进归档目录，改为**住进项目根 `prototype/`**（用项目的 `node_modules` 与组件库版本运行，见契约 §3.2）；归档 `ui-*/` **只留 `_notes.md` 交接件**。因此阶段一产物校验门禁查的是「项目 `prototype/` 有对应 `.vue`」+「`ui-*/_notes.md` 存在」，而不是「归档里有 `.vue`」。实现时原型**就地晋升**进 `src/views/<module>/`。

# 目的

阶段一产物用于：

- 把 PRD 的**业务语言**翻译为**开发契约**（领域模型 / 状态机 / 接口契约 / 权限 / 消息事件）
- **后端概设定稿主线契约，前端概设引用**；UI 由独立 UI 子 agent 经 openDesign 产出的**真组件原型**（Vue SFC）承载区域→组件、交互与视觉，与概设同步并行；各产物做支线时锚定同一个 S-xx 编号
- 是阶段二 ts-design 的设计基线：概设契约 + UI 原型直接输入详细设计
- 是阶段二「阶段一产物校验门禁」的校验对象（后端概设 + 前端概设 + UI 原型）

---

# 适用场景

阶段一**必须编写**概设（后端 + 前端两份），有页面场景时**必须产出 UI 原型**：

- 承接 PRD，进入前后端契约设计时
- 需求涉及多个角色 / 状态流转 / 接口对接时

以下情况**不需要**独立概设：

- PRD 已明确、无状态流转、无多角色差异的极简单需求（可直接进入详细设计）

# openDesign 设计规范层（内置资产，非外部依赖）

UI 产出以**内置的 openDesign 资产**为设计规范层：约束**视觉基调、布局规范、交互模式与组件选型方向基线**；组件库仍为 `@tiansu/ts-web-package`，二者分层不冲突。

- **约定位置**：规范层**随插件内置**，分三处（按许可与更新节奏三分，详见 `references/assets/open-design/README.md`）：

  | 层 | 位置 | 管什么 |
  | --- | --- | --- |
  | 契约 | `references/rules/ui-prototype-standard.md` | 原型结构：产出形态与接入前提、三步结构分析、五态与数据接入、样式边界、区域→组件映射、命名与落位 |
  | 品牌观感 | `references/design-systems/tiansu-web/DESIGN.md` + `tokens.css` | 色 / 字 / 间距 / 组件的天溯纪律 |
  | 工艺 | `references/rules/hifi-craft.md` + `references/assets/open-design/craft/` | 品牌无关通用工艺：反 AI 味 P0、排版、动效、无障碍、五态 |

- **读取时机**：独立 UI 子 agent 产出 UI 原型前，先读取上述资产（契约 + 品牌观感 + 按屏型取工艺）；组装顺序为 **契约 → 视觉 → 工艺 → 组件方向**（顺序即注入优先级）
- **缺失处理**：内置资产**随插件发布，不会缺失**，不设停机分支。若检测到文件确实不可读，属插件安装损坏，按安装问题处理，**不产出** UI 原型
- **零运行依赖**：规范层只含文本资产，**不含** daemon / MCP / agent 运行时 / 模型 key；下游用户项目**无需安装 openDesign**。openDesign 本体的 headless 能力（`od lint` / `od export`）为**可选增强**，且其入参为 HTML——SFC 形态下暂不适用，退化为 `references/rules/ui-prototype-standard.md` §11 的人工清单，**不中断产出**（见该文件 §12）
- **选型定位**：规范层给设计规范；原型由**真 `te-*` 组件组合**，`@tiansu/ts-web-package` 是它的运行时依赖（须整体 `app.use` 安装，见契约 §1）。组件选型在阶段一完成并被真实渲染验证，**阶段二不再重新选一遍**——Props/Events 的准确取值仍以 `ts-components` 核实为准。

# 编写边界

| 写（阶段一产物）                           | 不写（留给下游）                    |
| ------------------------------------------ | ----------------------------------- |
| 领域模型与实体关系                         | 数据库表结构、索引                  |
| 状态机与状态约束                           | 具体组件选型、组件 API              |
| 数据字典（类型/枚举翻译）                  | UI 细节、样式                       |
| 接口契约（路径/方法/场景）                 | 接口请求/响应字段明细               |
| 权限矩阵（接口 × 角色）                    | 鉴权实现方式                        |
| 消息事件清单                               | 消息中间件、推送通道                |
| 前端页面与路由清单                         | 前端状态管理、hooks 结构            |
| 前端 API 模块清单                          | 前端请求层实现、拦截器              |
| 页面承载内容与交互意图（UI 原型）         | 组件内部实现、Props/Events 细节     |
| 交互动作/反馈/状态覆盖（UI 原型）          | 交互逻辑实现、动画细节              |
| 组件组合与视觉方向（UI 原型，区域→组件）   | 组件 API 核实、样式代码             |
| 后端模块划分与关键逻辑                     | 后端类/方法级实现                   |

> 判断标准：给前后端各能"接得住"且不会做岔；接口字段明细、组件实现、真实组件 API 留给详细设计（ts-design）。
>
> **拆分边界**：主线契约只写在后端概设（§2），前端概设仅同步接口清单（§2）并编写前端支线；UI 由独立 UI 子 agent 经 openDesign **从 PRD 直接产出原型（Vue SFC）**承载区域→组件、交互与视觉，与前端概设并行、互不为输入，**不重复**定义领域模型 / 状态机 / 数据字典 / 权限 / 消息事件全文；页面清单与前端概设 §3.1 以 S-xx 对齐，不新增场景外页面。

# 主线与支线机制

- **主线**（后端概设 §2）是前后端公共契约，概设阶段**在后端概设定稿**；前端概设引用，前后端不得单方面改主线
- **前端支线**（前端概设 §3）按 S-xx 给页面与路由、API 模块
- **UI 产物**由独立 UI 子 agent 从 PRD S-xx 独立推导页面、经 openDesign 产出原型（Vue SFC），按 S-xx 给区域→组件、交互、状态覆盖与视觉方向，与前端概设并行
- **后端支线**（后端概设 §3）按 S-xx 给模块、接口实现、领域逻辑
- **执行方式**：主线程基于 PRD **并行分派前端/后端两个子 agent 生成概设**（各按 `references/templates/overview-be.md` / `references/templates/overview-fe.md`）；**UI 由独立 UI 子 agent 经内置 openDesign 规范层**产出原型（产出前先读 `references/rules/ui-prototype-standard.md` + `references/design-systems/tiansu-web/DESIGN.md`，按屏型取 `references/assets/open-design/craft/`）；各产物锚定同一 S-xx，经用户确认后**前后端分离**
- **并行草稿与对齐**：前后端概设并行生成、互不为输入：后端/前端 §2 契约以 PRD 为准起草为**待对齐草稿**；UI 页面以 PRD S-xx 为准直接推导，不依赖前端 §3.1。在 ⛔ 确认时「S-xx 对齐核对」环节**以后端概设 §2.4 定稿为准**对齐前端 §2；**前端 §3.1 页面清单与 UI 原型页面按 S-xx 双向核对**，不一致回到 PRD 判定（前端定路由/契约、UI 定区域→组件/交互/视觉），不动后端主线
- **前后端分离**：后端概设（主线契约）交付后端团队独立实现；前端概设 + 后端概设契约 + UI 原型作为前端 ts-design 输入继续走插件管线
- 一个场景可只在后端有产出（纯规则场景），不必每个场景都有前端页面；**纯规则 / 无页面场景 UI 不产出原型**，与前端概设 §3.1 对齐时留空说明
- 修改主线需回到产品需求（PRD）核对，并同步前端概设与 UI 原型

# 归档规范

## 存放目录

```
archive-spec/product/
```

## 文件命名

概设分别命名，版本号与迭代号保持一致：

```
后端概设：overview-be-V<MAJOR>.<MINOR>.<PATCH>_I<ITERATION>_<描述(≤6字)>.md
前端概设：overview-fe-V<MAJOR>.<MINOR>.<PATCH>_I<ITERATION>_<描述(≤6字)>.md
```

UI 产出**分两处落位**：原型 `.vue` 落**项目根 `prototype/`**（运行壳拷自 `references/assets/prototype-sandbox/`，依赖用项目的 `node_modules`），交接件 `_notes.md` 归档为**独立目录**，目录名与概设同版本/迭代：

```
<项目根>/prototype/
    Sxx_<页面名>.vue                  （真 te-* 组件组合，可构建可渲染）
    index.html / main.ts / vite.config.ts / tsconfig.json   （运行壳）

archive-spec/product/ui-V<MAJOR>.<MINOR>.<PATCH>_I<ITERATION>_<描述(≤6字)>/
    _notes.md                         （区域→组件映射交接件，见契约 §10）
```

> **原型只有一份**：归档里**不再存 `.vue` 副本**——可运行的那个文件才是真相。落点与命名唯一口径见 `references/rules/ui-prototype-standard.md` §3.2。

> **不再按状态拆份**：五态由文件内的演示场景切换器逐屏切换（契约 §5.3）。
> 旧形态的 `Sxx_<页面名>_<状态>.html` 拆份写法**作废**；多页时的 `index.html` 导航页**一并作废**（SFC 无「双击打开」这回事）。

> **命名唯一口径**以 `references/rules/ui-prototype-standard.md` §3.2 为准：场景号**下划线 + 两位补零**（`S01`），场景号与页面名之间用**下划线**连接（`S01_公告列表.vue`）；**不使用**连字符写法 `S-01-页面名`（该写法作废）。

版本号与迭代号与对应 PRD 保持一致；命名规则同 references/hard-gate.md「产物归档」。

示例：

```
overview-be-V1.0.0_I1_费用报销.md
overview-fe-V1.0.0_I1_费用报销.md
prototype/S01_费用填报.vue  +  archive-spec/product/ui-V1.0.0_I1_费用报销/_notes.md
overview-be-V2.1.0_I2_订单导出.md
overview-fe-V2.1.0_I2_订单导出.md
prototype/S01_订单列表.vue  +  archive-spec/product/ui-V2.1.0_I2_订单导出/_notes.md
```

# 质量检查清单

**后端概设：**

- [ ] 承接的 PRD 场景脊椎 S-xx 全部覆盖，无遗漏
- [ ] 领域模型 / 状态机 / 数据字典 / 接口契约 / 权限 / 消息事件六要素齐全
- [ ] 数据字典把 PRD 业务含义翻译为类型/枚举，未出现表结构
- [ ] 接口契约每个都挂了场景（S-xx），无未归属接口
- [ ] 权限矩阵为 ✓/空，范围查询按角色注明
- [ ] 状态约束（如编辑回草稿）已在状态机与关键逻辑中落实
- [ ] 后端支线按 S-xx 组织，锚点一致
- [ ] 文件命名符合规范，与 PRD 版本/迭代一致
- [ ] 概设已归档且经用户确认后，方可进入详细设计
- [ ] 已等待用户确认

**前端概设：**

- [ ] 主线契约全部来自后端概设，未在后端概设中的契约不得使用
- [ ] 接口清单与后端概设 §2.4 一致，无自行加字段
- [ ] 前端页面、API 模块按 S-xx 组织，与后端概设锚点一致
- [ ] 页面与路由清单已给出（区域→组件/交互/视觉由 UI 原型承载，此处不写组件级布局）
- [ ] 状态机 / 消息事件 / 权限与后端概设对齐（前端不展示状态机不允许的动作）
- [ ] 页面清单与 `<项目根>/prototype/` 下的原型以 S-xx 核对一致（有页面场景时）
- [ ] 文件命名符合规范，与后端概设版本/迭代一致
- [ ] 已等待用户确认

**UI 产出（真组件原型）：**

- [ ] 已读取内置规范层（`references/rules/ui-prototype-standard.md` + `references/design-systems/tiansu-web/` + 按屏型取 `references/assets/open-design/craft/`）后再产出，未读取/未按规范不产出
- [ ] 仅覆盖 PRD S-xx 推导页面，无场景外新增页面；页面清单与前端概设 §3.1 以 S-xx 核对一致

# 编写原则

- **契约优先**：主线在后端概设定稿，前端概设引用；UI 从 PRD + openDesign 直接产出原型，避免各做各的
- **单一事实源**：契约只写一次（后端概设），前端引用不重述；前端页面清单与 UI 原型同源自 PRD S-xx，确认时以 S-xx 对齐，不各写一套契约
- **锚点一致**：后端/前端概设与 UI 原型都对着同一个 S-xx 编号
- **UI 不单独成文**：UI 产物是 openDesign 产出的真组件原型（可构建、可渲染、可评审），不是概设文档，不产生 `overview-ui-*.md`
- **原型单一事实源**：原型 `.vue` 只住 `<项目根>/prototype/`，归档 `ui-*/` 只留 `_notes.md` 交接件；实现时原型**就地晋升**进 `src/views/<module>/`，沙箱中不保留副本（契约 §3.2）
- **设计规范层**：UI 产物结构/视觉/交互遵循**内置** openDesign 规范层（契约 `references/rules/ui-prototype-standard.md` + 品牌 `references/design-systems/tiansu-web/` + 工艺 `references/assets/open-design/craft/`），随插件发布、**零运行依赖**（组件库除外，见契约 §1）；组件库仍 `@tiansu/ts-web-package`
- **业务翻译**：把 PRD 的业务含义翻译为类型/枚举，不编造业务规则
- **宁简勿繁**：无状态流转、无多角色差异时不必强行堆结构

# 与阶段二的关系

阶段一产物（后端概设 + 前端概设 + UI 原型）构成阶段二「阶段一产物校验门禁」的校验对象。**概设确认后前后端分离**：后端概设（主线契约）交付后端团队独立实现；前端概设 + UI 原型（连同后端概设契约）作为阶段二输入，阶段二**不再重复需求分析**。

消费方式：

| 阶段一产物                  | 阶段二消费方式                                       |
| --------------------------- | ---------------------------------------------------- |
| 领域模型 / 状态机           | 设计文档「业务流程」直接引用                         |
| 数据字典                    | 设计文档「数据」类型/枚举                            |
| 接口契约                    | 设计文档「API 设计」契约                             |
| 权限矩阵                    | 设计文档「权限」+ 实现鉴权                           |
| 消息事件                    | 设计文档「交互 / 通知」                              |
| 后端支线（后端概设）        | 设计文档「模块设计」基线                             |
| 前端支线（前端概设）        | 设计文档「页面与组件」基线                           |
| UI 原型（`<项目根>/prototype/`） | 设计文档「页面设计」读 `.vue` 原型 → 组件级布局（区域→组件已在模板里）+ 晋升目标 `src/views/<module>/` |
| UI 交互 / 状态覆盖          | 设计文档「页面设计」交互与状态                       |
| UI 组件组合 / 视觉方向      | 设计文档「页面设计」组件选型基线（Props 仍以 `ts-components` 核实为准） |
