> PRD 是阶段一的**唯一输入**（前端概设、后端概设、UI 原型产出都从本文件派生，不各自向产品要料）。产品侧要确保以下信息在 PRD 中齐备，各环节才"接得住"：

| 环节 / 消费点                           | 产品侧需在 PRD 提供                                            | 所在章节     |
| --------------------------------------- | -------------------------------------------------------------- | ------------ |
| 前端概设 §3.1 页面与路由                | 页面级描述（每页做什么、页面间跳转、承载操作）                 | §2.2 / §3.1  |
| 前端概设 §3.2 API 模块                  | 页面承载的数据操作（查/增/删/改/导入/导出）                    | §3.1 / §4    |
| UI 原型（openDesign 子 agent）推导页面  | 场景脊椎 S-xx + 页面级描述（UI 据此推导页面）                  | §2.2 / §3.1  |
| UI 原型（openDesign 子 agent）交互/显隐 | 规则 Rx（触发 → 动作）、权限（角色×操作，影响按钮显隐/禁用）   | §4.1 / §7    |
| UI 原型（openDesign 子 agent）状态覆盖  | 各操作预期反馈（可选；Loading/Empty/Error 无则 UI 按惯例补齐） | §3.3 / §4    |
| 后端概设（若并行；主线契约）            | 业务实体与字段含义、状态流转、权限、消息/通知事件              | §3 / §5 / §7 |

> 若本次**不做后端概设**（后端由他处并行或引用既有契约），前端概设 §2 从**已归档的后端概设**同步接口清单即可，产品侧无需重复提供契约信息。
>
> **产品侧不需要提供**：页面布局/视觉/交互风格（归 openDesign + UI 子 agent）、组件选型与 API（归 `@tiansu/ts-web-package` + ts-components）、接口字段明细/数据字典（归后端概设 §2）。
>
> 填写原则：业务语言、可测试（FR 挂场景、Rx 给触发条件与动作、每条 FR 配 GWT），不写技术实现。每处 `<…>` 为占位，请替换为实际内容；不涉及的分支/流程请标注「无」，勿留空。
