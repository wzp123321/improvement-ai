# 屏型配方：运维手册（Runbook）

> 挂在 `ts-frontend-design` 下的**屏型配方**，不单独触发；由该技能的 Step 0 按屏型取用。
> 适用「服务运维手册 / on-call 指南 / SRE 文档 / 故障处置卡」这类**查阅型**单页。
> 源：OpenDesign `plugins/_official/examples/eng-runbook`（**改写，非翻译**）。
>
> **2026-09-10 形态变更**：原型由「自包含 HTML」改为「真 `te-*` 组件组合的 Vue 3 SFC」。
> 本屏型受影响最大——它原来的 §4 整节在讲 `data-ui-role` 词表缺口，而该词表已**废止**。

---

## 0. 先判定：这真的是运维手册吗

| 输入 | 判定 |
| --- | --- |
| 「运维手册 / on-call 指南 / 处置卡 / 服务说明」 | ✅ 用本配方 |
| 「运维看板 / 服务健康度 / 告警总览」 | ❌ 改走 `references/recipes/dashboard.md` |
| 「发布单 / 变更申请 / 值班排班表（要录入）」 | ❌ 那是有录入的表单，走 `references/recipes/list-page.md` + `te-dialog` > `te-form` |

**本屏型的关键性质：它是「查阅型文档」，不是「操作性页面」。** 这决定了三件事：

1. 大多数区是**静态内容**，不拉数 → 不套五态（见 §5）。
2. 访客在**故障中**打开它 → 信息可达性优先于视觉张力：先能扫到、能复制、能照着做。
3. 手册会**过期** → 必须显式标注版本与最后更新时间，否则没人敢信。

## 1. 值源与组件核实

- **值源 = 组件库主题**。不填 `:root`、不用 `--p-*`、不抄 tokens 快照；组件区**不在 `<style>` 里写颜色/字号/圆角**（`references/rules/ui-prototype-standard.md` §7）。
- 页面级布局间距取 `--te-space-*` 档位（4/8/12/16/20/24/32/40/48/64/80/96/160）。
- **代码/命令块是本屏型的自建区域**（组件库无代码块组件），其字体/底色/内边距是该区自己的样式，可以写在本页 `<style>` 里（§7.2 允许行）。
  等宽族与正文族分开计，字族总数仍 ≤ 2 + 系统 fallback（`references/rules/ui-prototype-standard.md` §4.3）。
- 组件真实 Props 与 Events 走 `ts-components`，`tsweb info` / `doc` / `demo` 核实，**禁止凭记忆**。

**本屏型必查的 craft 维度**（上游未声明 `od.craft.requires`，按 Te 场景补）：

| 维度 | 文件 | 本屏型在哪用 |
| --- | --- | --- |
| `state-coverage` | `references/assets/open-design/craft/state-coverage.md` | **仅**用于拉数区（告警实时状态、看板链接可达性），见 §5 |
| `accessibility-baseline` | `references/assets/open-design/craft/accessibility-baseline.md` | 表格可读、代码块可辨、颜色不作严重度唯一信号 |

> 上游把 `laws-of-ux` 用在了别处；本屏型不用——查阅型页面的价值是"找得到"，不是"层级美感"。

## 2. 骨架与区域 → 组件

| 区域 | 组件 | 承载 |
| --- | --- | --- |
| 页头 | `te-page-header`（+ `#extra`） | 服务名 + 负责团队 + 严重度分级 + 版本/最后更新 |
| 服务摘要 | `te-descriptions` | 服务摘要段 + 依赖清单 |
| 告警表 | `te-module-table` | 告警名 / 级别 / 含义 / 第一响应 |
| 看板与链接 | `te-link` 列表（页面自有容器） | 外部系统入口 |
| 常用操作 | **自建区域**（容器 + 等宽代码块） | 3–4 段 procedure，带可复制命令 |
| 值班表 | `te-module-table` | 周次 / 主 / 备 / 兜底 |
| 故障处置 | `te-steps` | 编号步骤 |

**编排规则**：

- 顺序即**使用顺序**：先认服务 → 再判告警 → 再找工具 → 再动手 → 最后兜底。不要按"好看"重排。
- 常用操作**必须带命令**，且命令是这一段的主体，不是附注。
- 映射**就在模板里**，不再写 `data-ui-role`（`references/rules/ui-prototype-standard.md` §9.2 已废止该词表）。

## 3. 各区域规格

### 3.1 页头（`te-page-header`）

- 必含：服务名、负责团队、**严重度分级**、版本号 + 最后更新时间。
- 最后更新时间不可省。运维手册没有日期的后果是没人知道它是否还成立。

### 3.2 告警表（`te-module-table`）

- 四列固定：**告警名 / 级别 / 含义 / 第一响应**。第四列是这张表存在的理由，不能省。
- 严重度用 `te-tag` 的**语义色 + 文字标签**，不要只用颜色——色盲用户与黑白打印都会失效（`hifi-craft.md` §6）。
- 每一列都要给 `checked: true`（`ColumnProps.checked` 是必填，漏掉整列不渲染）。
- 本表**通常不拉数**（手册是静态文档）→ 可以直接用静态列数据，不套 `:request-api`。
  ⚠ 但若改用 `te-module-table` 且需要操作列 / 分页 / 序号，仍须走 `:request-api`（`references/recipes/list-page.md` §5）。
  静态文档场景更稳妥的做法是用 `te-descriptions` 或普通表格语义，避开这个坑。

### 3.3 常用操作块（**自建区域**）

组件库没有"带命令的操作步骤"组件，这一区自建：

- 3–4 段，每段 = 标题 + 一句目的 + **可复制命令**。
- 命令规则：
  - 命令块内**不写 `$` / `>` 提示符**——复制时会带上，贴进终端就报错。
  - 多行命令保持原样缩进，不被折行破坏（`white-space: pre` 属于该自建区的样式，允许）。
  - 需要替换的变量用 `<尖括号>` 并**紧跟一行说明**其取值来源。
- 复制入口用 `navigator.clipboard.writeText` + `TeMessage` 反馈；**不手写图标 path**（`code-generation.md` 红线 #1），
  图标走 `te-button` 的 `icon` prop。
- ⚠ **危险命令**（回滚、删数据、轮换密钥）：独立 `danger` 语义 + 二次确认（`TeMessageBox`），不能用主色顶替（`references/rules/ui-prototype-standard.md` §8）。
- ⚠ **绝不放真实密钥 / token / 内网凭据**，即使是"示例"。占位写成 `<API_KEY>` 这类显式形状。

### 3.4 值班表（`te-module-table`）

- 四列：周次 / 主值班 / 备值班 / 兜底。周次需带**日期范围**，不能只写"第 3 周"。
- 人名是否可以进视觉稿，按你们的数据规范；不确定就用角色占位（`主值班（待定）`）。

### 3.5 故障处置（`te-steps`）

- 5 步左右，编号步骤。
- 每步是**可执行动作**，不是原则。写「确认 DB 连接池是否打满」，不写「关注数据库健康」。

## 4. ⚠ 常用操作区是「组件库覆盖不到的自定义区域」

旧形态下这一节在讨论 `data-ui-role` 词表缺一个 `procedure-list` 角色。**词表已废止**（`references/rules/ui-prototype-standard.md` §9.2），
问题换了个形状但没消失：**组件库里没有能承载「带命令的操作步骤列表」的组件**。

按 `references/rules/ui-prototype-standard.md` §2 的处置：

| 步骤 | 本屏型的落实 |
| --- | --- |
| 该区是自建区域 | 容器 + 等宽代码块，自己搭 |
| 需要「视觉方向」判断 | 一句话描述该区（如「故障中扫读优先：命令是视觉主体，说明是附注」） |
| 样式边界 | 该区**全部样式都可写**在本页 `<style>`（§7.2 允许行） |
| 仍不得越界 | **不用 `:deep()` 进任何组件内部**；不覆盖组件颜色/字号 |

> `references/rules/hifi-craft.md` 的反 AI 味 P0 对自建区域照常适用：无蓝紫强调色、无双色渐变、emoji 不作功能图标、不编造指标。

## 5. 状态：哪些区要五态，哪些不要

**不要给静态区套五态。** `references/rules/ui-prototype-standard.md` §5.1 的适用范围是「凡**拉取 / 接收数据**的区域」；运维手册多数区是静态正文。

| 区域 | 要五态？ |
| --- | --- |
| 服务摘要 / 依赖清单 / 常用操作 / 处置步骤 | ❌ 静态内容 |
| 告警表**实时状态**列 | ✅ 拉数 → 五态 |
| 看板与链接（探测可达性时） | ✅ 拉数 → 五态 |

拉数区仍须 `error ≠ empty`：**告警服务不可达**（error）与**当前无告警**（empty）在运维场景是完全不同的两件事，一个要人去查监控系统，一个是好消息。文案与视觉都必须区分。
五态由**变更 mock 返回**驱动，不用模板假分支（`references/rules/ui-prototype-standard.md` §5.3）。
