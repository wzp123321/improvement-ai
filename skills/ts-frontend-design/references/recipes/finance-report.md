# 屏型配方：财务报告（Finance Report）

> 挂在 `ts-frontend-design` 下的**屏型配方**，不单独触发；由该技能的 Step 0 按屏型取用。
> 适用「月度 / 季度 / 年度财务报告、经营分析、P&L 汇报页」这类**结账型**单页。
> 源：OpenDesign `plugins/_official/examples/finance-report`（**改写，非翻译**）。
>
> **2026-09-10 形态变更**：原型由「自包含 HTML」改为「真 `te-*` 组件组合的 Vue 3 SFC」。
> 本屏型受影响的点：KPI 条改用 `te-statistic`；图表区与「带合计行的 P&L 表」是自建区域；
> `data-ui-role` 词表已废止。

---

## 0. 先判定：发布稿，还是系统页

这一步决定后面一半的规则，**先判再动手**：

| 形态 | 特征 | 后果 |
| --- | --- | --- |
| **发布稿** | 一次成型、带署名、常要导出 PDF / 打印给外部或管理层 | 静态内容，**不套五态**；重点在 §4 数字自洽与密级 |
| **系统页** | 期间可切换、从接口取数、有刷新 | 拉数 → 五态齐全 + 期间选择控件 |

> 上游配方描述的是**发布稿**。若你们要做的是财务系统里的期次报表页，按下半段"系统页"走。

| 输入 | 判定 |
| --- | --- |
| 「财报 / Q3 报告 / 经营分析 / P&L」 | ✅ 用本配方 |
| 「费用明细表 / 报销单 / 台账（要录入筛选）」 | ❌ 那是 `references/recipes/list-page.md` 的管理页 |

## 1. 值源与组件核实

- **值源 = 组件库主题**。不填 `:root`、不用 `--p-*`、不抄 tokens 快照；组件区**不在 `<style>` 里写颜色/字号/圆角**（`references/rules/ui-prototype-standard.md` §7）。
- **KPI 条用 `te-card` > `te-statistic`**（`tsweb info statistic` 已核实：`value` / `title` / `prefix` / `suffix` / `precision` / `group-separator` / `formatter`）。数字族与等宽由组件与主题决定，**不在页面写 `font-variant-numeric`**。
- **图表区与带合计行的 P&L 表是自建区域**（组件库无图表组件；合计行承载方式见 §3.4），其样式可以写在本页 `<style>` 里（§7.2 允许行）。
- **不要照搬上游的 SaaS 指标族**（MRR / burn / runway）。按实际业务替换指标，Te 场景更可能是「营业收入 / 毛利率 / 回款额 / 应收账款周转」这类。

**本屏型必查的 craft 维度**：

| 维度 | 文件 | 本屏型在哪用 |
| --- | --- | --- |
| `state-coverage` | `references/assets/open-design/craft/state-coverage.md` | **仅系统页**，见 §6 |
| `accessibility-baseline` | `references/assets/open-design/craft/accessibility-baseline.md` | 表格可读、正负不靠颜色单一表意 |

> ⚠ **上游声明 `od.craft.requires: [rtl-and-bidi]`，本插件不采纳**：`rtl-and-bidi` 是阿拉伯语 / 希伯来语双向排版纪律，Te 的中文业务财务文档用不到。需要时再单独引入。

## 2. 骨架与区域 → 组件

| 区域 | 组件 | 承载 |
| --- | --- | --- |
| 报头 | `te-page-header`（+ `#extra`） | 主体 / 期间 / 密级标识 |
| KPI 条 | `te-card` > `te-statistic` × 4 | 口径名 + 金额 + delta |
| 收入趋势图 | **自建区域**（SVG 折线 + 面积） | 变化 |
| 成本结构图 | **自建区域**（SVG 柱状）+ 2–3 条说明 | 构成 |
| P&L 摘要 | `te-module-table` 或**自建区域**（见 §3.4） | 本期 vs 上期 |
| 主要客户 / 项目 | `te-module-table` | 名称 / 口径 / 金额 / 状态 |
| 结尾 | 页面自有容器 | 展望段 + 页脚署名 |

映射**就在模板里**，不再写 `data-ui-role`（`references/rules/ui-prototype-standard.md` §9.2 已废止该词表）。

**编排规则**：

- 顺序是**阅读顺序**：先结论（KPI）→ 再趋势 → 再结构 → 再明细 → 最后展望。不按"好看"重排。
- KPI 条 4 个，**不多不少**。财务头条超过 4 个等于没有头条。
- 图表**两张分工不同**：一张讲"变化"（趋势），一张讲"构成"（结构）。两张都讲变化 = 重复。

## 3. 各区域规格

### 3.1 报头（`te-page-header`）

- 必含三件：**报告主体**（公司 / 部门）、**期间**（明确到"2026 Q3"或"2026 年 1–9 月"）、**密级标识**。
- 密级标识保留上游的 `Confidential` 意图，落成 Te 的密级措辞（如「内部 / 秘密 · 财务」）。**视觉上要能被一眼看到**，不是页脚小字——可用 `te-tag` 的 danger/warning 语义承载，颜色 + 文字。
- 期间口径写清是**自然季**还是**财年季**——两者差一个月，是财务页最常见的歧义。

### 3.2 KPI 卡（`te-card` > `te-statistic`）

- 结构：**口径名 → 金额 → 同比/环比 delta**。口径名走 `title`（或 `#title` 槽），金额走 `value`。
- 单位**必须标在卡上**（元 / 万元 / 千元），用 `prefix` / `suffix` 表达，不能只在表头标一次。
- 小数位与千分位用 `precision` / `group-separator`——**用组件属性表达，不写 CSS**。
- delta 写全对比基准（「较上年同期」），不只有百分比；正负方向不能只靠颜色（`hifi-craft.md` §6）。

### 3.3 图表区（**自建区域**）

组件库没有图表组件，这是自建区，也是反 AI 味风险最集中的地方：

- **自绘 SVG，不引图表库**。折线 ≈ 一条 `<polyline>` + 一层淡面积填充；柱状 = N 个 `<rect>`。
- 坐标轴单位与刻度必须标；财务图没有单位的 Y 轴等于没有信息。
- 强调色只用于一处高亮（如本期柱子），不是每项一个色。accent 每屏 ≤ 2（`hifi-craft.md` §3）。
- 该区样式可全部写在本页 `<style>`，但仍**不得用 `:deep()` 进任何组件内部**。
- ⚠ 手绘 SVG 在这里是**合法的**：`code-generation.md` 红线 #1 禁止的是**手写图标路径**（图标走组件 `icon` prop）。图表不是图标，组件库不提供，只能自绘。

### 3.4 P&L 表

- 两列对比：**本期 / 上期**（可加变动额、变动率）。
- **合计行**加粗 + 上边框区分，不要与明细行同权重。
- ⚠ **合计行的承载方式未经真组件验证**：`te-module-table` 是否支持合计/汇总行尚未核实
  （需 `tsweb doc module-table` 确认）。若不支持，**该表作为自建区域处理**，
  而不是给组件加 `:deep()` 规则去造一个合计行——后者违反 `references/rules/ui-prototype-standard.md` §7.2。
  该判定须写进 `_notes.md` 未决问题。
- 若用 `te-module-table`：每列都要给 `checked: true`（必填，漏掉整列不渲染）；数字右对齐与等宽由列定义表达，不写 CSS。
- 单位全篇统一。**同一页混用"元"和"万元"是财务页最典型的不可信信号**。

## 4. ⚠ 数字的真伪与自洽（本配方与原配方的关键分歧）

上游原文写的是 *"If unspecified, assume a quarterly SaaS report and **pick believable numbers**"*，以及 *"every number ties to a labelled chart or table"*。两句在 Te 语境下都不够，必须替换为下面三条：

### 4.1 禁止无来源编造（P0）

编造指标是 `references/rules/hifi-craft.md` §5.6 的 P0 项。财务数字比看板数字更敏感——一份看不出是示例的假财报可能被当真。处理方式：

1. **有真实来源** → 使用，并在 `_notes.md` 注明口径与来源；
2. **无来源但需体现量级** → 示例值，并在**页面显眼处**加「示例数据」标识（不是藏在小字里）；
3. **连量级都不可知** → 用「—」或「待定」，**不要**编一个看起来合理的数字。

> 与 `references/recipes/dashboard.md` §4 同一条纪律，但财务场景下**标识必须更显眼**。

### 4.2 表内必须加总自洽

上游只要求"数字与有标注的图表/表格对应"，没要求表内自洽。财务页要补上：

- 收入 − 成本 = 毛利
- 毛利 − 费用 = 净利（或净亏损）
- 分项之和 = 合计

**对不上的财报，读者三秒就能发现，之后整页都不可信。** 这是本屏型最容易翻车、也最容易自查的一项。

### 4.3 数字书写规范（全篇统一）

| 项 | 规则 |
| --- | --- |
| 单位 | 全篇统一（元 / 千元 / 万元），每处金额可见或紧邻标注 |
| 千分位 | 一律加 |
| 负数 | 全篇统一写法（`-1,234` 或会计括号 `(1,234)`），**不混用** |
| 百分比 | 小数位数统一（1 位或 2 位），不混用 |
| 空值 | 用「—」，不要用 0 顶替（0 与无数据是两回事） |

## 5. 打印与导出（本屏型补充）

财务报告常被打印或导出 PDF，原型阶段就该照顾：

- 加 `@media print`：去背景色块、保留边框与文字对比、避免表行跨页断开。
  ⚠ 该块**只作用于自建区域与页面级布局**，不得用来改组件打印样式（`:deep()` 一律禁止）。
- 图表用 SVG 而非依赖背景色的表达，黑白打印仍可读。
- 密级标识与页脚署名必须在打印版保留——这是内部文档的合规要求，不是装饰。
- **不要**依赖仅在屏幕上可见的 hover 提示承载关键信息。

## 6. 状态

| 形态 | 处理 |
| --- | --- |
| 发布稿（§0） | 静态内容，**不套五态**（`references/rules/ui-prototype-standard.md` §5.1 只管拉数区） |
| 系统页 | 期间切换、取数的区各自五态齐全；`error ≠ empty`——「取数失败」与「当期无数据」是两件事 |

系统页的期间选择控件（`te-date-picker` / `te-date-switch`）置于 `te-page-header` 的 `#extra`，且**期间口径在控件上可见**，不让用户猜。
五态由**变更 mock 返回**驱动，不用模板假分支（`references/rules/ui-prototype-standard.md` §5.3）。
