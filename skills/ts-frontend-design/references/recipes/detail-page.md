# 屏型配方：详情页（Detail）

> 挂在 `ts-frontend-design` 下的**屏型配方**，不单独触发；由该技能的 Step 0 按屏型取用。
> 适用「XX 详情 / XX 明细 / XX 档案 / XX 单据查看」这类**只读为主的单记录页**。
> 源：**非上游抽取**——OpenDesign 182 份配方里没有中后台详情页。本配方由
> `references/rules/ui-prototype-standard.md` §3.3 骨架 + §5 五态 + §8 权限显隐 + §9 区域→组件映射编写。
>
> **2026-09-10 形态变更**：原型由「自包含 HTML」改为「真 `te-*` 组件组合的 Vue 3 SFC」。
> 区域不再靠 `data-ui-role` 词表标注，**区域就是组件本身**；值源改为组件库主题。

---

## 0. 先判定

| 输入 | 判定 |
| --- | --- |
| 「XX 详情 / 明细 / 查看 / 档案」 | ✅ 用本配方 |
| 「XX 列表 / 管理页」 | ❌ 改走 `references/recipes/list-page.md` |
| 「新增 / 编辑 XX」「XX 表单」 | ❌ 改走 `references/recipes/list-page.md` 的弹窗路径（`te-dialog` > `te-form`）；本配方只给**入口**，不承载录入 |
| 「XX 概览 / 驾驶舱」 | ❌ 改走 `references/recipes/dashboard.md` |

**列表页与详情页是一对**：列表给"哪一条"，详情给"这一条的全部"。多数中后台需求二者成对出现，判定时先确认要的是哪一个。

---

## 1. 值源与组件核实

- **值源 = 组件库主题**。不填 `:root`、不用 `--p-*`、不抄 tokens 快照，**不在 `<style>` 里写颜色/字号/圆角**（`references/rules/ui-prototype-standard.md` §7）。
- 页面级布局间距取 `--te-space-*` 档位，**不写随机 px**。
- **数字字段**（金额、数量、比率）的等宽与对齐**由组件属性表达**（`te-descriptions` / 表格列定义），不写 CSS。
- 组件真实 Props 与 Events 走 `ts-components`，`tsweb info` / `doc` / `demo` 核实，**禁止凭记忆**。
- 拉数区走组件的数据接入方式（明细子表同 `list-page` §5 的 `:request-api` 结论）。

**本屏型必查的 craft 维度**：

| 维度 | 文件 | 本屏型在哪用 |
| --- | --- | --- |
| `state-coverage` | `references/assets/open-design/craft/state-coverage.md` | 五态 + 动作后的状态反馈（主用，见 §6） |
| `laws-of-ux` | `references/assets/open-design/craft/laws-of-ux.md` | 信息分组、字段顺序、返回路径 |
| `accessibility-baseline` | `references/assets/open-design/craft/accessibility-baseline.md` | 状态徽标不靠颜色单一表意、字段标签与值的语义关联 |

## 2. 骨架与区域 → 组件

真组件形态下映射**就在模板里**（`references/rules/ui-prototype-standard.md` §9.1）：

| 区域 | 组件 | 承载 |
| --- | --- | --- |
| 页头 | `te-page-header`（+ `#extra`） | 业务名 + 唯一标识 / 状态徽标 / 返回 / 主操作组 |
| 关键字段 | `te-descriptions` | 编号 / 名称 / 状态 / 时间… |
| 分块 | `te-collapse` | 基本信息 / 业务信息 / 扩展信息 |
| 明细分页签 | `te-tabs` | 明细 / 关联 / 附件 / 变更记录 |
| 明细子表 | `te-module-table` | 同 `list-page` §3.3 表格规则 |
| 变更记录 | `te-timeline` > `te-timeline-item` | 时间 + 操作人 + 动作 + 结果 |
| 附件 | `te-upload`（只读态）/ `te-image` | 查看 / 下载 |
| 编辑入口 | `te-dialog` / `te-drawer` > `te-form` | 入口在页头，不在本页就地编辑（§5） |
| 加载失败 / 不存在 | `te-result` | 文案与重试 |

顺序即 §3.3 节奏，**不要重排**。`te-page-header` 内的状态徽标是**元素**（`te-tag`），不是独立区域。

---

## 3. 各区域规格

### 3.1 页头（`te-page-header`）

- 标题 = **业务名 + 唯一标识**（如「巡检单 PD-2026-0912」）——只有名字则两条记录无法区分，只有编号则不可读。
- 状态徽标紧跟标题，用 `te-tag`：**语义色 + 文字**，颜色不是唯一信号（§5 无障碍）。
- **返回路径必须存在**（面包屑或返回），且回到来源列表时**保留来源页的筛选与页码**——详情页最恼人的缺陷就是"返回后筛选没了"。
- 主操作每屏 **≤ 1** 个用主色，其余次按钮；危险操作独立 `danger` + 二次确认（§8）。

### 3.2 关键信息（`te-descriptions`）

- **列数固定**（中后台基准 2–3 列），不随视口逐字段重排——列数由组件属性给定，不写 CSS。
- 字段顺序按**业务阅读顺序**，不按数据库字段序；主键类信息（编号、名称、状态、时间）在前。
- 字段标签与值**成对**且语义关联（由 `te-descriptions` 的 item 结构保证）。
- **空值写「—」，不写 0、不写空字符串、不写"暂无"**——空与 0 是两回事，尤其数值字段。
- 信息过长时用 `te-collapse` 分块（基本信息 / 业务信息 / 扩展信息），首块默认展开。

### 3.3 明细分页签（`te-tabs`）

- 页签数量 **≤ 5**；超出考虑是否该拆成独立页。
- 每个页签内若是拉数区，**各自带自己的五态**（§5.1），不共用主区状态。
- 明细子表沿用 `references/recipes/list-page.md` §3.3 的表格规则（列对齐、数字右对齐、`edge` 态），但**通常不带分页**——超长时给"查看全部"进入筛选后的列表页。

### 3.4 变更记录（`te-timeline`）

- 用 `te-timeline` + `te-timeline-item`（`tsweb demo timeline` 已核实：`timestamp` / `placement` / `type` / `color` / `size` / `hollow` / `icon`）。
- 倒序（最新在上）；每条含**时间 + 操作人 + 动作 + 结果**。
- 动作前后状态变化要写出来（「已提交 → 已通过」），只写"审批"无法复原流转。
- 节点语义色（`type`）与业务状态对应，但**不靠颜色单一表意**——文字里要写明状态。
- 这是**追溯性证据**，不做装饰性时间线；空时给「暂无记录」而非隐藏该页签。
- 节点图标走 `icon` prop（组件库图标），**不手写 SVG path**（`code-generation.md` 红线 #1）。

### 3.5 附件（只读态）

- 详情页附件默认**只读态**（查看/下载），上传入口按权限显隐（§8）。
- 无附件是 `empty` 态，不是把区域整个藏掉——用户需要知道"这里本来有附件位"。

---

## 4. ⚠ 动作由状态机决定（本屏型核心）

详情页是**状态流转的入口**，`references/rules/ui-prototype-standard.md` §8 那条「不允许的动作不做入口」主要就落在这一屏。三种"不可用"必须分清：

| 情形 | 处理 | 反例 |
| --- | --- | --- |
| **状态机不允许**（这条记录当前状态下做不了） | **不出现该按钮** | 已完成的单子仍显示「提交」 |
| **权限不足** | 按权限矩阵**显隐**（§8） | 把无权限的动作灰着摆出来 |
| **前置条件未满足**（如需先选明细） | **可禁用，但须给原因** | 灰着不给理由 |

- 不可逆动作（作废、删除、驳回）独立 `danger` 语义 + **二次确认**，确认文案写清**后果**，不写"确定吗？"。
  SFC 形态下的实现：`TeMessageBox.confirm`（显式、类型可校验）。
- 动作执行后**状态变化必须让用户看见**——就地更新徽标与时间线，不要静默跳转回列表。
- **禁止用禁用态给"将来才可用"的动作占位**——那是在用按钮教用户猜规则。
- 按钮组按状态**动态生成**，不是把所有按钮写死后靠 `v-if` 摆——前者是状态机，后者容易漏。

---

## 5. 只读边界

- 详情页**默认只读**。编辑走 `te-dialog` / `te-drawer`（字段少）或独立表单页（字段多、涉流程），入口在页头主操作。
- **不在详情页做就地编辑**：会把"看"与"改"混成一件事，权限矩阵也失去落点（§8 的显隐规则需要明确的动作边界）。
- 但**必须给编辑入口**——只读不等于没有出路。
- 字段级权限（某些字段对某些角色不可见）按权限矩阵**隐藏字段本身**，不显示"无权限查看"占位。

---

## 6. 状态

详情页是**重度拉数**屏型（主区 + 各页签各自拉数），五态齐全：

| 状态 | 形态 |
| --- | --- |
| `loading` | 保留 `te-descriptions` 字段骨架，不塌陷；用组件内置加载态（§5.1） |
| `empty` | **单记录详情一般无 empty**——记录不存在即 404，走 error，文案讲清"该记录不存在或已删除" |
| `error` | 拉取失败：出了什么 + 可知原因 + 能做什么（重试）；与"记录不存在"文案不同 |
| `populated` | 默认态 |
| `edge` | 超长文本（截断 + 展开）、超长枚举换行、单条明细、百条明细、字段全空（整块给「—」+ 说明） |

行内控件态齐全：`hover` / `focus-visible` / `active` / `disabled` / `loading`——**均由组件库提供**，页面不自建（§5.4）。
